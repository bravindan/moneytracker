# Taste / Preferences
- Expects deleting a parent record (e.g., a monthly record) to cascade-delete all related child data (spending, expenses, investments) so that re-creating it starts fresh; dislikes orphaned records left behind. Confidence: 0.8
- Deleting a record that consumed money must not just remove the records — it must reverse their financial effects (revert/restore the account balances used to pay, e.g., reversing credit "used"/"remaining" via the same repay logic used when repaying a credit). Explicitly stated: deleting an expense category should remove all spending under it AND revert balances from the accounts that were used to pay the amount. Confidence: 0.8
- Expects wallet/account pickers AND account cards to display real computed values — "Available" balance for asset accounts (funded minus spent), "Remaining" for credit accounts, and per-account Total/Used/Balance rows — rather than static/placeholder labels or copy that defers the data to another screen (e.g., explicitly asked to remove "this month's funded balance is shown on the dashboard" text from account cards and show the actual numbers in place; re-reported when the investment screen's "Select account" wallet picker showed a hardcoded "Balance" label instead of the wallet's actual available figure — it must compute and show the real value). Confidence: 0.95
- Expects allocation/budget screens to display computed running balances live (e.g., total allocation 20,000 minus a new category of 5,000 shows "Balance: 15,000", updating as the user types) so the user never has to manually calculate how much remains to allocate. Confidence: 0.8
- Screens showing month-scoped financial data (e.g., the Accounts/Wallets screen) must reflect the month the user is viewing on the dashboard — passed via navigation params — rather than hardcoding the device's current month; otherwise deletions/updates in the viewed month appear stale and get reported as bugs (e.g., Cash "Used" still showing 500 after all expenditures and expense categories were deleted). Derived/aggregated views must recompute from source records so deletes and edits are reflected. Confidence: 0.7
- Wallet-to-wallet transfers must move only the entered amount: debit the source wallet's funded amount and credit the destination's by exactly that amount (e.g., transferring 1000 from a 10,000 Mobile Money wallet to a 500 Cash account yields 9,000 and 1,500), never resetting either balance to the transferred figure. Confidence: 0.8
